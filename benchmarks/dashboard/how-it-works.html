How Does a Computer Decide What to Do Next?

An interactive, visual journey through CPU cores, math algorithms, and the 7 decisions scx_optima makes in under 40 nanoseconds.

Written by Risheendra MN • rishindra.hackbox@gmail.com
The Big Picture • The Kitchen Analogy

Think of Your Computer Like a Busy 5-Star Restaurant

At any given second, your computer is trying to run hundreds of programs at once: Discord, Spotify, Chrome with 30 tabs, a 120 FPS game, and background system updates. But your CPU only has a few cores! How does it handle all of them without crashing or lagging?

👨‍🍳

1. The Chefs (CPU Cores)

Modern chips have two kinds of chefs:

  • Head Chefs (P-Cores): Super fast (5.0+ GHz). Great at quick, precision tasks like rendering game frames. There are only a few of them.
  • Line Cooks (E-Cores): Slower (3.0 GHz), but use very little electricity. Perfect for bulk jobs like compiling code or downloading files.
📋

2. The Food Orders (Tasks)

Different programs have totally different personalities:

  • The 120 FPS Video Game: A VIP customer who needs a bite of sushi every 8.33 milliseconds. If the chef is 1ms late, the screen freezes (frame drop).
  • The Code Compiler: A giant banquet order for 5,000 people. Doesn't care if an individual plate is 5ms late, as long as the entire meal finishes.
🍳

3. The Prep Table (L3 Cache)

Memory access speeds vary dramatically:

  • On the Cutting Board (L1/L2 Cache): Right in front of the chef. Takes 1 nanosecond to grab an ingredient.
  • In the Back Freezer (RAM): Walking to the pantry takes 100x longer! The scheduler tries to keep chefs at the same prep table so they don't lose their rhythm.
Step-by-Step Logic • The 7 Questions

The 7 Questions scx_optima Asks Before Running a Program

Whenever a program wants to execute, scx_optima runs through this lightning-fast decision tree in about 20 to 40 nanoseconds (faster than light travels 40 feet!):

DECISION 01 Safety Check

"Are you glued to a specific chair?" (Pinning Guard)

Some tasks (like hardware drivers or kernel background workers) are strictly locked to one CPU (e.g. CPU 9). If you try to schedule them on another CPU, the system crashes!

The Rule: If nr_cpus_allowed == 1, bypass all smart queues and send it straight to that core's personal local queue (SCX_DSQ_LOCAL).

Why it matters: This one rule prevented a fatal 44-second kernel watchdog stall that crashed other schedulers during big compilation jobs!

DECISION 02 Fast-Path

"Are you passing a hot dish straight to a partner?" (WAKE_SYNC)

When you download a file or test network speeds with iperf3, the sender sends a packet and immediately goes to sleep waiting for the receiver to read it.

The Secret: Instead of putting the receiver at the back of the queue, hand execution to them right on the same core! The packet is already sitting in L1/L2 cache.

The Result: This is why scx_optima reached 171.58 Gbps local network speed while others got stuck at 64 Gbps!

DECISION 03 Math: Density

"Are you a Sprinter or a Marathon Runner?" (Task Density)

The scheduler calculates your **Task Density** ($\rho_i$) using a simple formula:

$$\text{Density} = \frac{\text{Importance Weight} \times 1,000,000}{\text{Average Run Time in Microseconds}}$$
  • A Game Tick: Runs for only 240 µs. $\text{Density} = (100 \times 1,000,000) / 240 = \mathbf{416,666}$ → Huge density! Route to Head Chef P-cores!
  • A Compiler: Runs for 18,000 µs continuously. $\text{Density} = (100 \times 1,000,000) / 18,000 = \mathbf{5,555}$ → Low density. Route to Line Cook E-cores!
DECISION 04 Hardware Bitops

"Which Chef is Free Right This Microsecond?" (O(1) Scan)

How do you check if any of your cores are sitting idle without wasting time?

Hardware Trick: The CPU keeps a single 64-bit integer where each bit represents a core (1 = Idle, 0 = Busy). A single assembly instruction checks it in 3 nanoseconds!

If a P-core is green, the game server is handed directly to that core with zero queue waiting.

DECISION 05 Quantum Sizing

"How long do you get to use the stove?" (Time Slice)

If you let one program hold the CPU for too long, mouse clicks feel sluggish. But if you switch programs too frequently, the CPU wastes all its energy switching instead of working!

• Interactive / Game Tasks: 3 milliseconds (quick turn so nobody waits).
• Heavy Compilation Tasks: 20 milliseconds (long turn to max out CPU pipeline).

Result: GCC compiler jobs run 5.4x faster than standard Linux CFS!

DECISION 06 Smith's Rule

"When is your ticket deadline?" (Greedy WSPT)

In 1956, mathematician Wayne Smith proved that ordering jobs by Weight / Length guarantees the lowest average waiting time for everyone.

$$\text{Virtual Deadline} = \text{Current Time} + \frac{\text{Time Slice} \times 100}{\text{Priority Weight}}$$

VIP tasks with high weight receive an earlier virtual deadline, moving them to the front of the line automatically.

DECISION 07 Branch & Bound

"What if all Head Chefs are already cooking?" (Preemption Cut-In)

Imagine an urgent 120 FPS game frame arrives, but all 4 Performance cores are busy compiling Linux code. If the game waits in line, you get a lag spike!

Branch & Bound Lower Bound Test: Can we pause a compilation worker and let the game frame run right now? If the math shows that pausing saves more time than it costs, the kernel sends a hardware interrupt, kicks the compiler off the core, runs the game frame in 1.7ms, and then resumes the compiler!

The Outcome: 0.00% dropped frames across 2,000 players. Zero hitching.

Vocabulary • Plain-English Dictionary

All the Terms Explained Simply

Ever felt confused by computer science buzzwords? Here is what every single term actually means in plain English:

Operating System Kernel

The fundamental master program that runs directly on the bare metal hardware. It acts like the restaurant manager, making sure programs don't crash into each other or steal memory.

CPU Scheduler

The traffic cop inside the kernel. When 100 programs want to run but you only have 12 CPU cores, the scheduler decides who goes next, for how long, and who has to wait.

P-Core vs. E-Core

Modern chips have big fast Performance cores (5.0+ GHz) for urgent work, and smaller, energy-saving Efficiency cores (3.0 GHz) for background work.

Time Slice (Quantum)

The timer given to a program before the CPU pauses it to let someone else have a turn. Usually between 3 and 20 milliseconds.

Context Switch

When the CPU stops doing one thing and starts doing another. Like putting down your math homework and picking up your history essay. It takes time, so doing it too often slows everything down!

CPU Cache (L1, L2, L3)

Microscopic memory chips built directly inside the CPU. 100 times faster than RAM, but very small. Keeping your program's data in the cache is the secret to high performance.

Preemption

When an urgent task (like moving your mouse or drawing a game frame) interrupts a background task (like file indexing) before its timer expires, so your computer never feels frozen.

Priority Inversion

An annoying bug where an urgent task gets stuck waiting in line behind an unimportant background task. scx_optima uses mathematical Branch-and-Bound to prevent this!

Frame Drop (Game Stutter)

At 120 frames per second, a new frame must be rendered every 8.33 milliseconds. If the scheduler is even 1 millisecond late, the screen stutters. scx_optima achieves 0.00% drops!

eBPF

A revolutionary technology in Linux that lets developers safely run custom code inside the kernel at hardware speeds without rebooting or risking a blue-screen crash.

sched_ext

A brand-new Linux kernel feature that lets programmers write custom operating system schedulers in Rust and C using eBPF!

Work-Conserving

A fancy mathematical term meaning: "If there is work to do, no chef sits around doing nothing." Guarantees 100% of your multi-core processor is put to work!
