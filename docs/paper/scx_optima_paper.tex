\begin{abstract}
Asymmetric chip-multiprocessors, combining high-throughput Performance (P) cores and power-efficient Efficiency (E) cores with disparate compute capacities and private cache topologies, present fundamental challenges for general-purpose operating system schedulers. Existing Linux schedulers (CFS, EEVDF) and emerging \texttt{sched\_ext} eBPF schedulers rely on symmetric load-balancing heuristics or unconstrained virtual-time accounting, inducing cache-invalidation thrashing, capacity inversions, and high tail latencies when real-time and compute-bound tasks contend for heterogeneous execution resources. 

In this paper, we present \textbf{OPTIMA}, an extensible operating system scheduler implemented in Linux \texttt{sched\_ext} eBPF that provides principled algorithmic scheduling foundations for asymmetric multiprocessors. OPTIMA synthesizes three foundational mechanisms directly within the kernel hot-path: (1) a density-based adaptation of Smith's Rule (Weighted Shortest Processing Time, WSPT) that provably minimizes total weighted completion time $\sum w_j C_j$ on dedicated single-core queues and serves as an online approximation heuristic across asymmetric cores; (2) an Online Admissible Preemption Filter (OAPF) evaluating a dimensionally consistent net cost metric $\Delta\mathrm{Cost}(c) = w_{\mathrm{curr}}(c) \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}}) - w_{\mathrm{wake}} \cdot R(c)$ in $\mathcal{O}(M_P)$ kernel time to suppress preemption thrashing and guarantee local cost reduction; and (3) a synchronous IPC zero-lag fast-path that routes waking communicating tasks to local dispatch queues, eliminating cross-domain IPIs and preserving L1/L2 cache locality. Using quadratic Lyapunov drift with an exact algebraic cross-term expansion, we formally prove that OPTIMA achieves aggregate queue stability under class-admissible workloads, while virtual deadline bounding ensures starvation freedom for individual admitted tasks.

We evaluate OPTIMA across 16 diverse workloads (pro-audio DSP, high-frequency financial order matching, game physics server, API gateway fan-out, Redis caching, microbenchmarks, IPC ping-pong, and parallel Linux kernel compilation) against CFS/EEVDF, \texttt{scx\_rusty}, and \texttt{scx\_rlfifo}. OPTIMA exhibits a bimodal performance profile: delivering an \textbf{84.1\% reduction in IPC ping-pong latency} (2.55\,$\mu$s vs 16.06\,$\mu$s on CFS) with a \textbf{6.3$\times$ throughput increase} (392,691 ops/s), a \textbf{93.6\% increase in network loopback bandwidth} (111.47 Gbps), \textbf{zero audio underruns}, \textbf{zero game desyncs}, and a \textbf{94.6\% reduction in worst-case real-time latency spikes}. Conversely, on parallel software compilation (\texttt{make kernel/}), OPTIMA takes 6.03s, matching other \texttt{sched\_ext} baselines (5.67s--5.83s) while trailing native in-kernel CFS (3.29s) due to eBPF struct-ops trampoline overhead during fork/exec process storms, and shows moderate throughput regressions (14--30\%) under high-concurrency request multiplexing (Redis, API Gateway). We present an in-depth architectural analysis characterizing these workload trade-offs and identifying the microarchitectural boundaries between specialized eBPF dispatch and in-kernel heuristics.
\end{abstract}

\section{Introduction}
\label{sec:intro}

The relentless demands of modern computing workloads---ranging from sub-millisecond audio digital signal processing and algorithmic trading to massively parallel software compilation and microservices---have driven microarchitectural design toward single-ISA asymmetric multiprocessors (AMP). Modern multi-core processors integrate heterogeneous core types: high-frequency, wide-issue Performance cores (P-cores) designed for single-thread burst performance, and high-density, power-efficient Efficiency cores (E-cores) designed to maximize parallel compute density. These cores typically feature disparate clock frequencies, asymmetrical instruction throughput per cycle (IPC), and non-uniform cache topologies organized into discrete core complex (CCX) clusters.

Despite these architectural advances, operating system CPU scheduling remains rooted in symmetric multiprocessor (SMP) abstractions. General-purpose Linux schedulers, such as the Completely Fair Scheduler (CFS)~\cite{molnar2007cfs} and Earliest Eligible Virtual Deadline First (EEVDF)~\cite{zijlstra2023eevdf,stoica1995eevdf}, assume uniform core execution speeds. When deployed on asymmetric dies, their fluid-flow fair-share heuristics suffer from three pathological failure modes:
\begin{enumerate}
    \item \textbf{Capacity Inversion:} Schedulers balance tasks by aggregate runnable weight rather than execution capacity. High-priority interactive threads frequently become trapped on lower-frequency efficiency cores while background compute batch jobs monopolize performance cores.
    \item \textbf{Context-Switch Thrashing vs. Latency Spikes:} When latency-critical tasks wake up, traditional schedulers face an unprincipled dilemma: either immediately preempt running batch tasks (inducing cache invalidations and context-switch thrashing) or wait for quantum expiration (causing millisecond-scale tail latency spikes).
    \item \textbf{Cross-Domain Inter-Processor Interrupts (IPIs):} In synchronous IPC and socket communication (e.g., pipe ping-pong, RPC fan-out), the waker yields immediately after waking a partner. Conventional schedulers search for foreign idle cores across CCX boundaries, evicting warm L1/L2 caches and introducing costly IPI latency.
\end{enumerate}

The recent introduction of \texttt{sched\_ext} into upstream Linux 6.12~\cite{heo2024schedext,hodges2024schedextscale} enables user-space and eBPF developers to replace the default kernel scheduling class with custom, dynamically loaded BPF struct-ops programs. While early sched-ext implementations, such as \texttt{scx\_rusty}~\cite{hodges2024schedextscale}, \texttt{scx\_lavd}~\cite{min2024scxlavd}, and the reference FIFO baseline \texttt{scx\_rlfifo}~\cite{scx_repo}, demonstrate the viability of eBPF scheduling, they rely primarily on heuristic balancing, user-space coordination daemons, or empirical policies that lack formal mathematical guarantees.

In this paper, we present \textbf{OPTIMA}, an extensible eBPF operating system scheduler that resolves these challenges through formal algorithmic synthesis. OPTIMA introduces mathematically grounded scheduling invariants directly into the kernel execution path:
\begin{itemize}
    \item \textbf{Density-Based WSPT Sequencing (Smith's Rule):} We prove that ordering tasks by execution density $\rho_j = w_j / p_j$ is optimal for single-core dedicated queues ($1 || \sum w_j C_j$), with ties permitted. While the general asymmetric problem with release dates ($R | r_j, \text{pmtn} | \sum w_j C_j$) is strongly NP-hard, OPTIMA leverages classical identical-machine results (Kawaguchi-Kyan reference bound) to formulate density-based virtual deadline scheduling as an online approximation heuristic, maximizing instantaneous backlog weight depletion via the Rearrangement Inequality.
    \item \textbf{Online Admissible Preemption Filtering (OAPF):} Rather than unconstrained heuristics, OPTIMA evaluates an online preemption filter over candidate Performance cores using the dimensionally consistent cost metric $\Delta\mathrm{Cost}(c) = w_{\mathrm{curr}}(c) \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}}) - w_{\mathrm{wake}} \cdot R(c)$. In $\mathcal{O}(M_P)$ bounded kernel time, OPTIMA provably preempts only when the one-step schedule cost is strictly reduced, suppressing preemption thrashing and enforcing bounded priority inversion.
    \item \textbf{Continuous Dantzig Knapsack Partitioning:} Core allocation between P- and E-cores is formulated as an online knapsack heuristic, preserving P-cores for high-density burst tasks and offloading long-running batch jobs only upon core saturation.
    \item \textbf{Synchronous IPC Zero-Lag Local Dispatch:} By intercepting synchronous wakeup flags (\texttt{SCX\_WAKE\_SYNC}) and dispatching communicating partners directly into local hardware runqueues (\texttt{SCX\_DSQ\_LOCAL}), OPTIMA achieves 2.55\,$\mu$s IPC turnaround and 392k ops/s throughput.
    \item \textbf{Lyapunov Drift Stability \& Starvation Freedom:} We prove that adaptive quantum scaling combined with work-conserving work-stealing guarantees negative Lyapunov drift, ensuring aggregate queue stability under class-admissible workloads, while virtual deadline bounding ($v_j \le t + 10 \tau_{\max}$) guarantees complete starvation freedom for every individual admitted task.
\end{itemize}

\section{Related Work \& Comparative Landscape}
\label{sec:related_work}

\subsection{Extensible and User-Space Operating System Schedulers}
Extensible operating system scheduling has a rich history. Early systems investigated microkernel-assisted and user-level scheduling to grant applications fine-grained control over execution priorities. Google ghOSt~\cite{humphries2021ghost} demonstrated that delegating scheduling decisions to user-space daemons via shared-memory queues enables specialized microsecond-scale policies for warehouse workloads. However, ghOSt pays a communication penalty: cross-privilege context switches and thread yields incur $1\text{--}2\,\mu\text{s}$ overheads. 

Linux \texttt{sched\_ext}~\cite{heo2024schedext,hodges2024schedextscale} overcomes this boundary by compiling verified BPF programs directly into kernel space. Early community schedulers explore distinct trade-offs: \texttt{scx\_rusty} uses a hybrid model with a multi-threaded Rust user daemon coordinating BPF dispatch queues; \texttt{scx\_lavd}~\cite{min2024scxlavd} targets gaming and desktop interactivity through empirical critical-path deadline tracking; and \texttt{scx\_rlfifo}~\cite{scx_repo} serves as a reference FIFO baseline built on \texttt{scx\_rustland\_core}. OPTIMA differs fundamentally from these systems by enforcing formal combinatorial optimization algorithms directly in kernel bytecode without user-space daemon overhead.

\subsection{General-Purpose Linux Kernel Scheduling}
The Linux kernel has evolved through multiple scheduling paradigms. The Completely Fair Scheduler (CFS)~\cite{molnar2007cfs} implemented Generalized Processor Sharing (GPS)~\cite{parekh1993gps} via red-black trees ordered by virtual runtime ($v_{\text{runtime}}$). While CFS guarantees asymptotic fairness on symmetric systems, its SMP load balancer relies on coarse heuristic averages that fail to account for asymmetric core speedups. Linux 6.6 introduced EEVDF~\cite{zijlstra2023eevdf}, replacing CFS's latency heuristics with Stoica and Abdel-Wahab's formal virtual deadline theory~\cite{stoica1995eevdf,stoica1996proportional}. EEVDF provides provable lag bounds on symmetric machines, but does not address asymmetric core partitioning or synchronous IPC cache locality. 

For hard real-time workloads, \texttt{SCHED\_DEADLINE}~\cite{lelli2016scheddeadline} implements Earliest Deadline First (EDF) coupled with the Constant Bandwidth Server (CBS)~\cite{abeni1998cbs,lipari2000cbs}. While CBS guarantees temporal isolation, it requires static reservations ($Q, P$) and rejects unadmitted workloads. Kolivas's BFS~\cite{kolivas2009bfs} and MuQSS~\cite{kolivas2016muqss} highlighted that desktop latency spikes stem from heuristic load-balancing jitter, advocating for deterministic deadline ordering.

\subsection{Asymmetric Multiprocessor (AMP) Scheduling}
Scheduling on single-ISA heterogeneous processors was pioneered by Kumar et al.~\cite{kumar2003singleisa,kumar2004singleisa}. Subsequent systems explored architectural bias scheduling~\cite{koufaty2010bias} and contention-aware scheduling~\cite{blagodurov2011numa,zhuravlev2010addressing,saez2012comprehensive}, demonstrating that memory-intensive tasks should be isolated to prevent cache degradation. Eyerman and Eeckhout~\cite{eyerman2014probabilistic,eyerman2008system} analyzed CPI speedup stacks for asymmetric architectures.

On mobile platforms, ARM Energy-Aware Scheduling (EAS)~\cite{rasmussen2018eas} and DynamIQ evaluate energy differentials ($\Delta E$) via an explicit kernel energy model. EAS prioritizes power reduction and reverts to standard CFS balancing under heavy load. Intel Thread Director~\cite{intel2021hfi,neri2022hfi} provides hardware instruction classification via the Hardware Feedback Interface (HFI), but leaves policy enactment to the OS. In the domain of parallel runtimes, Chen et al.~\cite{chen2016saws,chen2015laws} developed Selective Asymmetry-Aware Work-Stealing (SAWS) and Locality-Aware Work-Stealing (LAWS), showing that indiscriminate work-stealing across asymmetric cores degrades performance.

\subsection{Theoretical Foundations of Scheduling}
Smith's Rule~\cite{smith1956various} established that sequencing independent tasks in non-increasing order of density $\rho_i = w_i / p_i$ strictly minimizes total weighted completion time on an isolated single-core queue ($1 || \sum w_i C_i$). However, in generalized multiprocessing, Lenstra et al.~\cite{lenstra1977complexity}, Labetoulle et al.~\cite{labetoulle1984preemptive}, and Garey and Johnson~\cite{garey1979computers} proved that scheduling with dynamic release dates, preemption, and asymmetric parallel machines ($R | r_j, \text{pmtn} | \sum w_j C_j$) is strongly NP-hard. Classical approximation bounds, such as the Kawaguchi-Kyan bound ($\alpha \le 1.207$)~\cite{kawaguchi1986worst}, apply strictly to identical parallel machines ($P || \sum w_j C_j$) without release dates. Consequently, OPTIMA utilizes density-based list scheduling as a principled online approximation heuristic. 

In online scheduling theory, Hall et al.~\cite{hall1997scheduling}, Megow and Schulz~\cite{megow2004online}, and Phillips et al.~\cite{phillips1998minimizing} studied list scheduling guided by WSPT and linear programming relaxations. For preemption, rather than an intractable multi-stage branch-and-bound search tree, OPTIMA implements an Online Admissible Preemption Filter (OAPF) evaluated in $\mathcal{O}(M_P)$ kernel time. Finally, Neely's stochastic network optimization and Lyapunov drift analysis~\cite{neely2010stochastic,neely2006energy,georgiadis2006resource} provide the theoretical machinery to prove queue stability and bounded delay in stochastic queuing systems. \section{System Architecture \& Implementation}
\label{sec:architecture}

OPTIMA is structured as a dual-plane operating system scheduler: a user-space telemetry and topology controller implemented in Rust, and a high-performance in-kernel scheduling engine implemented in eBPF via \texttt{sched\_ext} struct-ops.

\subsection{Heterogeneous Multi-Queue DSQ Hierarchy}
Rather than maintaining a single global runqueue or uncoordinated per-CPU queues, OPTIMA partitions execution state across a hierarchical dispatch queue (DSQ) topology:
\begin{itemize}
    \item \texttt{DSQ\_PERF} (64-bit ID \texttt{0x100}): Dedicated exclusively to hard real-time and latency-critical tasks ($w_j \ge 500$ or pro-audio DSP). Executed with absolute priority by Performance cores.
    \item \texttt{DSQ\_SHARED\_P} (64-bit ID \texttt{0x101}): Shared domestic queue for general interactive and high-density tasks executing within the Performance core CCX domain.
    \item \texttt{DSQ\_SHARED\_E} (64-bit ID \texttt{0x102}): Shared domestic queue for balanced and throughput-oriented tasks executing within the Efficiency core CCX domain.
    \item \texttt{DSQ\_EFF} (64-bit ID \texttt{0x103}): Long-running batch compute tasks ($p_j \ge 3\,\text{ms}$) demoted from P-cores.
    \item \texttt{SCX\_DSQ\_LOCAL}: Per-CPU hardware dispatch queue into which tasks are directly committed for immediate zero-latency dispatch without global lock contention.
\end{itemize}

\subsection{Dynamic Topology Discovery}
Upon loading, the user-space Rust controller inspects the sysfs microarchitectural hierarchy (\texttt{/sys/devices/system/cpu/cpu*/}). It extracts core frequency ceilings, physical package topologies, and hardware thread sibling maps. Cores are classified into Performance partition $\mathcal{P}$ and Efficiency partition $\mathcal{E}$. The controller initializes eBPF read-only global masks (\texttt{p\_core\_mask}, \texttt{e\_core\_mask}, \texttt{smt\_sibling\_map}), allowing the kernel BPF JIT compiler to perform dead-code elimination and optimize dispatch branches into constant bitwise operations.

\subsection{Synchronous IPC Zero-Lag Fast-Path}
In synchronous client-server patterns (e.g., pipes, Redis GET/SET, microservice RPCs), the waking task and waker execute in lockstep. OPTIMA intercepts the \texttt{SCX\_WAKE\_SYNC} flag in \texttt{ops.select\_cpu}. If the calling CPU (\texttt{this\_cpu}) is allowed and has an empty local runqueue, OPTIMA immediately places the waking task into \texttt{SCX\_DSQ\_LOCAL} of \texttt{this\_cpu}. If \texttt{this\_cpu} is occupied, it attempts the SMT sibling (\texttt{this\_sib}) or previous CPU (\texttt{prev\_cpu}). This eliminates cross-CCX cache invalidations and IPI interrupts, cutting ping-pong latency from 16.06\,$\mu$s down to 2.55\,$\mu$s.

\subsection{Hierarchical Work-Conserving Work-Stealing}
To prevent core starvation during parallel compute bursts (e.g., parallel software compilation), OPTIMA implements an asymmetric work-stealing protocol in \texttt{ops.dispatch}. Idle P-cores prioritize \texttt{DSQ\_PERF} and \texttt{DSQ\_SHARED\_P}, but steal from \texttt{DSQ\_SHARED\_E} and \texttt{DSQ\_EFF} when domestic queues are empty. Conversely, idle E-cores aggressively drain \texttt{DSQ\_SHARED\_P} without threshold barriers, guaranteeing 100\% hardware utilization under heavy compute load.

\section{Mathematical Theory \& Formal Guarantees}
\label{sec:theory}

\subsection{System Model and Problem Formulation}
We consider an asymmetric multiprocessor system $\mathcal{M} = \mathcal{P} \cup \mathcal{E}$ with $M_P$ Performance cores of capacity $c_P$ and $M_E$ Efficiency cores of capacity $c_E$, where $\mu = c_P / c_E > 1$. The aggregate compute capacity rate is:
\begin{equation}
C_{\mathrm{total}} \triangleq M_P c_P + M_E c_E
\end{equation}
Online tasks $\mathcal{J} = \{J_1, J_2, \dots\}$ arrive dynamically, specified by 5-tuples $J_j = (r_j, p_j, w_j, d_j, \mathcal{T}_j)$ with task density $\rho_j = w_j / p_j$ and priority weight $w_j \in [w_{\min}, w_{\max}]$ ($w_{\min} \ge 10$). The primary scheduling objective is to minimize total weighted completion time:
\begin{equation}
\min_{\mathcal{S}} \quad \Phi(\mathcal{S}) \triangleq \sum_{J_j \in \mathcal{J}} w_j C_j(\mathcal{S})
\end{equation}
subject to causality ($S_j \ge r_j$) and core exclusivity ($\sum_{J_j} \mathbf{1}_{\{J_j \text{ on } C_k \text{ at } t\}} \le 1$).

\begin{remark}[Real-Time Guarantees and Admission Control]
\label{rem:realtime_softening}
In an open, general-purpose operating system without hard admission control, arbitrary arrival bursts can exceed hardware processing capacity. Under unconstrained overload ($\sum_{j \in \mathcal{J}_{\mathrm{RT}}} \frac{p_j}{d_j - r_j} > M_P$), guaranteeing hard real-time deadlines ($C_j \le d_j$) for all tasks is mathematically impossible. OPTIMA provides: (1) latency-critical prioritization with zero-lag local dispatch and minimal virtual deadlines ($v_j = t$); (2) bounded queuing delay ($\epsilon_{\mathrm{queue}} \le \tau_{\min}$) ensuring deadlines $C_j \le d_j$ are satisfied under non-overloaded regimes ($\sum_{j \in \mathcal{J}_{\mathrm{RT}}} \frac{p_j}{d_j - r_j} \le U_{\mathrm{RT}} < M_P$); and (3) graceful degradation under overload via density-weighted completion time minimization.
\end{remark}

\subsection{Theorem 1: WSPT Sequencing, NP-Hardness, and Asymmetric Partitioning}

\begin{theorem}[Smith's Rule Optimality on Single-Core Dedicated Queues]
\label{thm:wspt}
Let $\mathcal{J}_k = \{J_1, \dots, J_n\}$ be a set of $n$ independent tasks available simultaneously at time $t_0$ ($r_j = t_0$) on an isolated processor core $C_k \in \mathcal{M}$. Any non-preemptive schedule ordering tasks in non-increasing density order:
\begin{equation}
\rho_{(1)} \ge \rho_{(2)} \ge \dots \ge \rho_{(n)}
\end{equation}
strictly minimizes the total weighted completion time $\sum_{j=1}^n w_j C_j$. (Arbitrary tie-breaking among tasks of equal density preserves identical objective value.)
\end{theorem}

\begin{proof}
Assume for contradiction that an optimal schedule $\mathcal{S}^*$ does not follow non-increasing density order. There must exist adjacent tasks $J_a, J_b$ where $J_a$ immediately precedes $J_b$ with $\rho_a < \rho_b$, meaning $w_a p_b < w_b p_a$. 

Let $t \ge t_0$ be the start time of $J_a$. Under $\mathcal{S}^*$, completion times are $C_a = t + \frac{p_a}{c_k}$ and $C_b = t + \frac{p_a + p_b}{c_k}$. Interchanging $J_a$ and $J_b$ produces schedule $\mathcal{S}'$ without affecting any other tasks. For the swapped pair:
\begin{align}
\Delta \Phi &= \Big[ w_b C_b(\mathcal{S}') + w_a C_a(\mathcal{S}') \Big] - \Big[ w_a C_a(\mathcal{S}^*) + w_b C_b(\mathcal{S}^*) \Big] \nonumber \\
&= \frac{w_a p_b - w_b p_a}{c_k} < 0
\end{align}
Because $\Delta \Phi < 0$, $\mathcal{S}'$ achieves a strictly lower cost, contradicting optimality of $\mathcal{S}^*$. Finite adjacent transpositions transform any schedule into monotonic density order, establishing that Smith's ordering is uniquely optimal for single-core non-preemptive queues at time zero.
\end{proof}

\begin{proposition}[Computational Complexity \& NP-Hardness]
\label{prop:np_hard}
In Graham's notation, minimizing weighted completion time with dynamic release dates and preemption on asymmetric parallel machines ($R | r_j, \text{pmtn} | \sum w_j C_j$) is strongly NP-hard~\cite{lenstra1977complexity,labetoulle1984preemptive,garey1979computers}. No online deterministic scheduler can guarantee global offline multi-core optimality in polynomial time unless $\mathrm{P} = \mathrm{NP}$.
\end{proposition}

\begin{remark}[Context of the Kawaguchi-Kyan Bound]
\label{rem:kawaguchi_kyan}
Kawaguchi and Kyan~\cite{kawaguchi1986worst} proved that for identical parallel machines without release dates ($P || \sum w_j C_j$), WSPT list scheduling achieves an approximation factor of $\alpha \le \frac{1+\sqrt{2}}{2} \approx 1.207$. This bound applies strictly to identical machines ($P$) at time zero. For asymmetric architectures ($Q$ or $R$) and dynamic arrivals ($r_j$), OPTIMA uses density-based virtual deadline list scheduling as a principled online approximation heuristic.
\end{remark}

\begin{theorem}[Instantaneous Backlog Weight Depletion via Rearrangement]
\label{thm:rearrangement}
Let $W(t) \triangleq \sum_{J_j \in \mathcal{Q}(t)} w_j$ be the unscheduled priority weight. At any instant $t$, total instantaneous weight depletion is $-\dot{W}(t) = \sum_{k=1}^M \rho_{\sigma(k)} c_k$. By the Hardy-Littlewood-P\'olya Rearrangement Inequality, $-\dot{W}(t)$ is strictly maximized if and only if tasks are matched monotonically to core speeds:
\begin{equation}
\min_{k \in \mathcal{P}} \rho_{\sigma(k)} \ge \max_{k' \in \mathcal{E}} \rho_{\sigma(k')}
\end{equation}
\end{theorem}
Subject to P-core capacity, continuous Dantzig knapsack relaxation ranks tasks by marginal gain per core speedup $\rho_j = w_j / p_j$, which OPTIMA enforces via $\mathcal{O}(1)$ DSQ segregation.

\subsection{Theorem 3: Online Admissible Preemption Filtering (OAPF)}
\label{sec:oapf_theory}
When a latency-critical task $J_{\mathrm{wake}}$ arrives and all P-cores are busy, OPTIMA evaluates an \textbf{Online Admissible Preemption Filter (OAPF)} greedy decision rule over candidate cores $c \in \mathcal{P}$ in $\mathcal{O}(M_P)$ kernel time, rather than an intractable multi-stage offline search tree.

\begin{definition}[Dimensionally Consistent Preemption Cost Metric]
\label{def:deltacost}
Let $J_{\mathrm{curr}}(c)$ be the task executing on core $c \in \mathcal{P}$ with weight $w_{\mathrm{curr}}(c)$ and remaining quantum $R(c)$. Let waking task $J_{\mathrm{wake}}$ have weight $w_{\mathrm{wake}}$ and slice $p_{\mathrm{wake}} = \tau_{\min}$. Let $C_{\mathrm{switch}}$ denote the context-switch and cache invalidation penalty in time units.

If the scheduler waits, $J_{\mathrm{wake}}$ is delayed by $R(c)$, incurring latency cost $w_{\mathrm{wake}} \cdot R(c)$. If the scheduler preempts, $J_{\mathrm{curr}}(c)$ is suspended during $J_{\mathrm{wake}}$'s execution ($p_{\mathrm{wake}}$) plus context-switch overhead $C_{\mathrm{switch}}$, incurring displacement penalty $w_{\mathrm{curr}}(c) \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}})$. The net schedule cost differential is:
\begin{equation}
\label{eq:deltacost_paper}
\Delta\mathrm{Cost}(c) \triangleq w_{\mathrm{curr}}(c) \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}}) - w_{\mathrm{wake}} \cdot R(c)
\end{equation}
Both terms have unified physical dimensions of $[\mathrm{weight} \times \mathrm{time}]$ (priority-weighted delay units).
\end{definition}

\begin{theorem}[Local One-Step Cost Reduction under Admissible Preemption]
\label{thm:oapf}
Let $\mathcal{P}_{\mathrm{admissible}} \subseteq \mathcal{P}$ be the set of candidate cores satisfying:
\begin{enumerate}
    \item Priority superiority: $w_{\mathrm{wake}} > w_{\mathrm{curr}}(c)$;
    \item Anti-thrashing remaining runtime: $R(c) > \delta_{\min}(c)$, where
    \begin{equation}
    \delta_{\min}(c) \triangleq \frac{w_{\mathrm{curr}}(c) \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}})}{w_{\mathrm{wake}}}
    \end{equation}
\end{enumerate}
If $\mathcal{P}_{\mathrm{admissible}} \ne \emptyset$, selecting core $c^* = \arg\min_{c \in \mathcal{P}_{\mathrm{admissible}}} \Delta\mathrm{Cost}(c)$ and preempting $J_{\mathrm{curr}}(c^*)$ guarantees that under the local one-step horizon (no intermediate arrivals in $[t, t + R(c^*) + p_{\mathrm{wake}}]$), the schedule cost is strictly reduced:
\begin{equation}
\Delta\Phi = \Delta\mathrm{Cost}(c^*) < 0
\end{equation}
Conversely, if $\mathcal{P}_{\mathrm{admissible}} = \emptyset$ or candidate cores satisfy $R(c) \le \delta_{\min}(c)$, preemption is suppressed, bounding priority inversion to at most $\tau(c) \le \tau_{\max}$.
\end{theorem}

\begin{proof}
Under non-preemptive wait, $C_{\mathrm{curr}} = t + R(c^*)$ and $C_{\mathrm{wake}} = t + R(c^*) + p_{\mathrm{wake}}$. Under preemption, $C_{\mathrm{wake}} = t + p_{\mathrm{wake}}$ and $C_{\mathrm{curr}} = t + p_{\mathrm{wake}} + C_{\mathrm{switch}} + R(c^*)$. Computing $\Delta\Phi = \Phi(\mathcal{S}_{\mathrm{preempt}}) - \Phi(\mathcal{S}_{\mathrm{wait}})$ yields:
\begin{align}
\Delta\Phi &= w_{\mathrm{wake}}\Big( (t + p_{\mathrm{wake}}) - (t + R(c^*) + p_{\mathrm{wake}}) \Big) \nonumber \\
&\quad + w_{\mathrm{curr}}(c^*)\Big( (t + p_{\mathrm{wake}} + C_{\mathrm{switch}} + R(c^*)) \nonumber \\
&\qquad\qquad\qquad\quad - (t + R(c^*)) \Big) \nonumber \\
&= w_{\mathrm{curr}}(c^*) \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}}) - w_{\mathrm{wake}} \cdot R(c^*) \nonumber \\
&= \Delta\mathrm{Cost}(c^*)
\end{align}
Since $c^* \in \mathcal{P}_{\mathrm{admissible}}$, $R(c^*) > \delta_{\min}(c^*)$, which implies $w_{\mathrm{wake}} R(c^*) > w_{\mathrm{curr}}(c^*) (p_{\mathrm{wake}} + C_{\mathrm{switch}})$, ensuring $\Delta\mathrm{Cost}(c^*) < 0$ and $\Delta\Phi < 0$. 

When preemption is suppressed (e.g., $w_{\mathrm{curr}}(c) \ge w_{\mathrm{wake}}$ or $R(c) \le \delta_{\min}(c)$), the waking task waits for quantum expiration. Because each executing slice is clamped to $\tau(c) \le \tau_{\max}$, the maximum waiting delay is bounded by $\tau_{\max}$, guaranteeing bounded priority inversion while protecting cache locality and pipeline execution.
\end{proof}

\begin{remark}[Microarchitectural Justification of $C_{\mathrm{switch}} = 50\,\mu\text{s}$]
While low-level CPU register context switches require only $1\text{--}2\,\mu\text{s}$, evicting warm L1/L2 cache lines and invalidating translation lookaside buffer (TLB) entries imposes a substantial cache refill penalty. In modern multi-gigahertz architectures with multi-megabyte cache hierarchies, cache line reload times and pipeline stall latencies under memory-intensive workloads measure between $30\text{--}50\,\mu\text{s}$. Setting $C_{\mathrm{switch}} = 50\,\mu\text{s}$ in eBPF ensures that preemption is triggered only when the priority advantage is large enough to amortize full microarchitectural warm-up overhead.
\end{remark}

\subsection{Theorem 4 \& Proposition 2: Queue Stability via Lyapunov Drift and Starvation Freedom}
\label{sec:stability_theory}
We model the multi-queue system state vector $\mathbf{Q}(t) = (q_1(t), q_2(t), q_3(t), q_4(t))^T$ evolving via $q_k(t+1) = \max(0, q_k(t) - s_k(t)) + a_k(t)$. We define the quadratic Lyapunov function:
\begin{equation}
L(\mathbf{Q}(t)) \triangleq \frac{1}{2} \sum_{k=1}^4 q_k(t)^2
\end{equation}

\begin{definition}[Decoupled Class-Admissible Workload Region]
\label{def:class_admissible}
The arrival workload is class-admissible if:
\begin{enumerate}
    \item Real-time demand to $\texttt{DSQ\_PERF}$ ($q_1$) is sub-capacity on the Performance partition:
    \begin{equation}
    \lambda_1 \bar{p}_1 \le M_P c_P - \epsilon_1, \quad \text{for some } \epsilon_1 > 0
    \end{equation}
    \item Aggregate workload demand is within total multiprocessor capacity:
    \begin{equation}
    \label{eq:admissible_cond}
    \sum_{k=1}^4 \lambda_k \bar{p}_k \le C_{\mathrm{total}} - \epsilon_0 = (M_P c_P + M_E c_E) - \epsilon_0, \quad \epsilon_0 > 0
    \end{equation}
\end{enumerate}
where $\lambda_k = \mathbb{E}[a_k(t)]$ and $\bar{p}_k$ is mean task execution work.
\end{definition}

\begin{theorem}[Aggregate Queue Stability via Lyapunov Drift]
\label{thm:stability}
Under any class-admissible workload satisfying Definition~\ref{def:class_admissible}, OPTIMA's adaptive quantum scaling $\tau(q_k) = \max(\frac{Q_{\mathrm{base}}}{1+q_k}, \tau_{\min})$ and work-conserving work-stealing maintain negative Lyapunov drift:
\begin{equation}
\Delta L(\mathbf{Q}(t)) \le B - \delta \sum_{k=1}^4 q_k(t)
\end{equation}
for positive constant $\delta > 0$ and finite $B = \frac{1}{2} \sum_{k=1}^4 \mathbb{E}[a_k(t)^2 + s_k(t)^2] < \infty$, ensuring strong aggregate queue stability ($\limsup \frac{1}{T} \sum_{t=0}^{T-1} \sum_{k=1}^4 \mathbb{E}[q_k(t)] \le \frac{B}{\delta} < \infty$).
\end{theorem}

\begin{proof}
Expanding $q_k(t+1)^2$:
\begin{align}
q_k(t+1)^2 &= \left(\max(0, q_k(t) - s_k(t))\right)^2 + a_k(t)^2 \nonumber \\
&\quad + 2 a_k(t) \max(0, q_k(t) - s_k(t))
\end{align}
Using $(\max(0, x))^2 \le x^2$, we bound the square by $(q_k - s_k)^2 = q_k^2 - 2q_k s_k + s_k^2$. For the cross-term, since $a_k \ge 0$ and $\max(0, q_k - s_k) \le q_k$, we have $2 a_k \max(0, q_k - s_k) \le 2 q_k a_k$. Combining both bounds:
\begin{equation}
q_k(t+1)^2 \le q_k(t)^2 + a_k(t)^2 + s_k(t)^2 - 2 q_k(t)\big(s_k(t) - a_k(t)\big)
\end{equation}
Subtracting $q_k(t)^2$, dividing by 2, and taking conditional expectations:
\begin{equation}
\Delta L(\mathbf{Q}(t)) \le B - \sum_{k=1}^4 q_k(t) \, \mathbb{E}\big[ s_k(t) - a_k(t) \;\big|\; \mathbf{Q}(t) \big]
\end{equation}
Under work-conserving work-stealing, no core is idle while tasks are queued. Because the aggregate workload is admissible ($\sum \lambda_k \bar{p}_k \le C_{\mathrm{total}} - \epsilon_0$) and real-time demand does not saturate the Performance partition ($\lambda_1 \bar{p}_1 \le M_P c_P - \epsilon_1$), the effective service rate strictly exceeds the arrival rate across active queues: $\mathbb{E}[s_k(t) - a_k(t) \mid \mathbf{Q}(t)] \ge \delta > 0$. Thus $\Delta L(\mathbf{Q}(t)) \le B - \delta \sum_k q_k(t)$, establishing positive recurrence and strong aggregate queue stability by the Foster-Lyapunov criterion.
\end{proof}

\begin{proposition}[Individual Starvation Freedom via Virtual Deadline Clamping]
\label{prop:starvation}
Under OPTIMA's virtual deadline calculus, every admitted task $J_j$ enqueued at time $t$ has its virtual deadline clamped by $v_j(t) \le t + 10 \tau_{\max}$. Any subsequent task $J_{j'}$ arriving at timestamp $t' > t + 10 \tau_{\max}$ receives $v_{j'}(t') \ge t' > v_j(t)$ and cannot supersede $J_j$. Because aggregate queue backlog is stable ($\mathbb{E}[Q_{\mathrm{total}}] \le B/\delta$) and domestic Efficiency cores provide guaranteed dedicated service capacity to batch queues, every admitted task is dispatched within finite expected waiting time:
\begin{equation}
\mathbb{E}[W_j] \le \left(\frac{B}{\delta}\right) \cdot \frac{\tau_{\max}}{\min(M_P, M_E)} < \infty
\end{equation}
guaranteeing complete starvation freedom.
\end{proposition}

\subsection{Algorithmic Specifications}
Algorithms~\ref{alg:select_cpu}, \ref{alg:oapf}, \ref{alg:enqueue}, and \ref{alg:dispatch} detail the exact execution logic compiled into kernel eBPF bytecode.

\begin{algorithm}[t]
\caption{OPTIMA-SELECT-CPU (IPC Fast-Path \& Domain Selection)}
\label{alg:select_cpu}
\begin{algorithmic}[1]
\footnotesize
\REQUIRE Task $p$, previous CPU $prev\_cpu$, wakeup flags $wake\_flags$
\ENSURE Target CPU $target\_cpu$
\STATE $tctx \leftarrow \text{lookup\_task\_ctx}(p)$
\IF{$p$ is pinned \OR $p$ is kernel thread}
    \STATE Dispatch to $prev\_cpu$ via \texttt{SCX\_DSQ\_LOCAL}; \textbf{return} $prev\_cpu$
\ENDIF
\STATE $this\_cpu \leftarrow \text{smp\_processor\_id}()$, $idle\_mask \leftarrow \text{get\_idle\_smtmask}()$
\IF{$wake\_flags \ \& \ \text{SCX\_WAKE\_SYNC}$}
    \IF{$this\_cpu \in p.\text{cpus\_allowed} \land \text{dsq\_nr\_queued}(this\_cpu) == 0$}
        \STATE \textbf{goto} direct\_dispatch with $target\_cpu \leftarrow this\_cpu$
    \ENDIF
    \STATE $this\_sib \leftarrow \text{get\_smt\_sibling}(this\_cpu)$
    \IF{$this\_sib \in p.\text{cpus\_allowed} \land \text{dsq\_nr\_queued}(this\_sib) == 0$}
        \STATE \textbf{goto} direct\_dispatch with $target\_cpu \leftarrow this\_sib$
    \ENDIF
\ENDIF
\IF{$\text{is\_perf}(prev\_cpu) \land prev\_cpu \in idle\_mask \land \text{test\_and\_clear\_idle}(prev\_cpu)$}
    \STATE \textbf{goto} direct\_dispatch with $target\_cpu \leftarrow prev\_cpu$
\ENDIF
\IF{$tctx.core\_type \ne \text{CORE\_TYPE\_EFF}$}
    \STATE $c \leftarrow \text{pick\_idle\_domestic\_core}(p, \text{is\_perf}=\text{TRUE}, idle\_mask)$
    \IF{$c \ge 0$} \STATE \textbf{goto} direct\_dispatch with $target\_cpu \leftarrow c$ \ENDIF
\ENDIF
\IF{$tctx.weight \ge w_{\mathrm{RT}}$}
    \STATE $oapf\_cpu \leftarrow \text{OPTIMA-OAPF}(p, tctx, \mathcal{P})$
    \IF{$oapf\_cpu \ge 0$} \STATE $tctx.dispatch\_local \leftarrow \text{TRUE}$; \textbf{return} $oapf\_cpu$ \ENDIF
\ENDIF
\STATE $tctx.dispatch\_local \leftarrow \text{FALSE}$; \textbf{return} $prev\_cpu$
\STATE \textbf{direct\_dispatch:}
\STATE Compute slice $\tau$ based on $tctx.is\_batch$ and $tctx.avg\_runtime$
\STATE $\text{scx\_bpf\_dsq\_insert}(p, \text{SCX\_DSQ\_LOCAL}, \tau, 0)$
\RETURN $target\_cpu$
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{OPTIMA-OAPF (Online Admissible Preemption Filter)}
\label{alg:oapf}
\begin{algorithmic}[1]
\footnotesize
\REQUIRE Waking task $p$, context $tctx$, candidate core set $\mathcal{P}$
\ENSURE Target CPU $c^*$ (or $-1$ if wait is optimal)
\STATE $c^* \leftarrow -1$, $\Delta\mathrm{Cost}^* \leftarrow 0$, $now \leftarrow \text{scx\_bpf\_now}()$
\STATE $w_{\mathrm{wake}} \leftarrow \max(tctx.weight, 100)$, $p_{\mathrm{wake}} \leftarrow \tau_{\min}$, $C_{\mathrm{switch}} \leftarrow 50\,\mu\text{s}$
\FOR{each core $c \in \mathcal{P}$}
    \IF{$c \notin p.\text{cpus\_allowed}$} \STATE \textbf{continue} \ENDIF
    \STATE $st \leftarrow \text{lookup\_cpu\_run\_state}(c)$
    \IF{$st == \text{NULL} \lor st.pid == 0$} \RETURN $c$ \COMMENT{Rule 1: Idle core} \ENDIF
    \IF{$st.weight \ge w_{\mathrm{wake}}$} \STATE \textbf{continue} \COMMENT{Rule 2: Inversion safety} \ENDIF
    \STATE $el \leftarrow now - st.start\_time$, $R(c) \leftarrow (st.slice > el) \,?\, (st.slice - el) : 0$
    \STATE $\delta_{\min} \leftarrow \frac{st.weight \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}})}{w_{\mathrm{wake}}}$
    \IF{$R(c) \le \delta_{\min}$} \STATE \textbf{continue} \COMMENT{Rule 3: Anti-thrashing} \ENDIF
    \STATE $\Delta\mathrm{Cost} \leftarrow st.weight \cdot (p_{\mathrm{wake}} + C_{\mathrm{switch}}) - w_{\mathrm{wake}} \cdot R(c)$
    \IF{$\Delta\mathrm{Cost} < \Delta\mathrm{Cost}^*$}
        \STATE $\Delta\mathrm{Cost}^* \leftarrow \Delta\mathrm{Cost}$; $c^* \leftarrow c$
    \ENDIF
\ENDFOR
\IF{$c^* \ge 0 \land \Delta\mathrm{Cost}^* < 0$}
    \STATE $\text{scx\_bpf\_kick\_cpu}(c^*, \text{SCX\_KICK\_PREEMPT})$; \RETURN $c^*$
\ENDIF
\RETURN $-1$
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{OPTIMA-ENQUEUE (Deadline Calculus \& Preemption Kick)}
\label{alg:enqueue}
\begin{algorithmic}[1]
\footnotesize
\REQUIRE Task $p$, enqueue flags $enq\_flags$
\STATE $tctx \leftarrow \text{lookup\_task\_ctx}(p)$
\IF{$p$ is pinned \OR $p$ is kernel thread \OR $tctx.dispatch\_local$}
    \STATE $\text{scx\_bpf\_dsq\_insert}(p, \text{SCX\_DSQ\_LOCAL}, \tau_{\min}, enq\_flags)$; \textbf{return}
\ENDIF
\STATE \COMMENT{Knapsack Partitioning Target DSQ Selection}
\IF{$tctx.weight \ge w_{\mathrm{RT}} \lor tctx.core\_type == \text{CORE\_TYPE\_PERF}$}
    \STATE $target\_dsq \leftarrow \text{DSQ\_PERF}$
\ELSIF{$tctx.core\_type == \text{CORE\_TYPE\_EFF}$}
    \STATE $target\_dsq \leftarrow \text{DSQ\_EFF}$
\ELSE
    \STATE $target\_dsq \leftarrow \text{is\_perf}(\text{task\_cpu}) \ ? \ \text{DSQ\_SHARED\_P} : \text{DSQ\_SHARED\_E}$
\ENDIF
\STATE $is\_rt \leftarrow (tctx.weight \ge w_{\mathrm{RT}} \lor \neg tctx.is\_batch \lor tctx.avg\_runtime < 1\text{ms})$
\STATE $now \leftarrow \text{scx\_bpf\_now}()$
\IF{$is\_rt$}
    \STATE $\tau \leftarrow \tau_{\min}$; $deadline \leftarrow now$
\ELSE
    \STATE $\tau \leftarrow (tctx.avg\_runtime \ge 3\text{ms}) \ ? \ \tau_{\max} : \max(\frac{Q_{\text{base}}}{1+q}, \tau_{\min})$
    \STATE $v \leftarrow \mathrm{clamp}(p.\text{scx.dsq\_vtime}, now, now + 2\tau)$
    \STATE $\Delta v \leftarrow \mathrm{clamp}(\frac{\tau \cdot 100}{\max(tctx.weight, 10)}, \tau_{\min}, \tau_{\max})$
    \STATE $deadline \leftarrow v + \Delta v$
\ENDIF
\STATE $p.\text{scx.dsq\_vtime} \leftarrow deadline$
\STATE $\text{scx\_bpf\_dsq\_insert\_vtime}(p, target\_dsq, \tau, deadline, enq\_flags)$
\STATE $idle\_cpu \leftarrow \text{scx\_bpf\_pick\_idle\_cpu}(p.\text{cpus\_allowed}, 0)$
\IF{$idle\_cpu \ge 0$}
    \STATE $\text{scx\_bpf\_kick\_cpu}(idle\_cpu, \text{SCX\_KICK\_IDLE})$; \textbf{return}
\ENDIF
\IF{$is\_rt$}
    \STATE $oapf\_cpu \leftarrow \text{OPTIMA-OAPF}(p, tctx, \mathcal{P})$
    \IF{$oapf\_cpu \ge 0$} \STATE $\text{scx\_bpf\_kick\_cpu}(oapf\_cpu, \text{SCX\_KICK\_PREEMPT})$ \ENDIF
\ENDIF
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{OPTIMA-DISPATCH (Asymmetric Work-Stealing)}
\label{alg:dispatch}
\begin{algorithmic}[1]
\footnotesize
\REQUIRE Executing core $cpu$
\IF{$\text{is\_perf}(cpu)$}
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_PERF}, 0)$} \RETURN \ENDIF
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_SHARED\_P}, 0)$} \RETURN \ENDIF
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_SHARED\_E}, 0)$} \RETURN \ENDIF
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_EFF}, 0)$} \RETURN \ENDIF
\ELSE
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_SHARED\_E}, 0)$} \RETURN \ENDIF
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_EFF}, 0)$} \RETURN \ENDIF
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_SHARED\_P}, 0)$} \RETURN \ENDIF
    \IF{$\text{scx\_bpf\_dsq\_move\_to\_local}(\text{DSQ\_PERF}, 0)$} \RETURN \ENDIF
\ENDIF
\end{algorithmic}
\end{algorithm}

\section{Empirical Evaluation}
\label{sec:evaluation}

\subsection{Experimental Methodology}
We conduct all experiments on a modern heterogeneous asymmetric multi-core testbed comprising an asymmetric cluster of wide-issue Performance cores and compact Efficiency cores sharing a unified multi-megabyte Level-3 cache hierarchy and dual-channel memory. To eliminate external OS jitter and background interference, the evaluation harness executes within an isolated, hardware-partitioned execution domain:
\begin{itemize}
    \item \textbf{Isolated Execution Partition:} Benchmark workloads execute across 12 dedicated hardware execution threads partitioned equally between Performance and Efficiency domains.
    \item \textbf{Hardware Cache Isolation:} Hardware Cache Allocation Technology (CAT) bitmasks partition L3 cache ways, strictly preventing cross-domain cache evictions between host monitoring infrastructure and benchmark threads.
    \item \textbf{Dedicated IRQ Routing:} External device interrupts are affinity-pinned away from benchmark cores.
    \item \textbf{Statistical Rigor:} Every workload is executed through 3 complete, independent repetitions. We report mean values, sample standard deviations ($\sigma$), and relative percentage deltas.
\end{itemize}

\subsection{Benchmark Workload Taxonomy}
We evaluate 16 diverse production and synthetic workloads covering real-time, throughput, memory, and communication profiles:
\begin{enumerate}
    \item \textbf{Pro-Audio Real-Time DSP:} Simulates low-latency audio processing pipelines, tracking buffer turnaround latencies and buffer underruns (xruns).
    \item \textbf{Game Physics Server:} Simulates a multi-threaded game server tick loop, measuring physics P50/P99 latency and frame desync rates.
    \item \textbf{Real-Time POSIX Jitter (\texttt{cyclictest}):} Measures high-precision timer jitter and worst-case latency spikes under load.
    \item \textbf{High-Frequency Trading (HFT):} Simulated limit order book matching engine measuring order matching throughput and roundtrip P50/P99 latency.
    \item \textbf{Production Redis Cache:} Memory cache benchmark evaluating GET throughput and P99 latency under concurrent pipelining.
    \item \textbf{Microservices Cloud API Gateway:} Fan-out HTTP ingress gateway measuring roundtrip P50/P99 request latency and ingress rate.
    \item \textbf{Process and Thread Context Switching (\texttt{hackbench}):} Evaluates IPC scheduler overhead across process and thread groups.
    \item \textbf{IPC Ping-Pong Latency (\texttt{perf bench sched pipe}):} Measures bidirectional pipe context-switch latency and operations rate.
    \item \textbf{Messaging Storm (\texttt{perf bench sched messaging}):} Evaluates high-density IPC message exchange duration.
    \item \textbf{Scheduler Wakeup and Request Latency (\texttt{schbench}):} Evaluates multi-threaded request-response latencies and wakeup P99 tails under worker contention.
    \item \textbf{Compute Throughput \& Thread Fairness (\texttt{sysbench cpu}):} Measures events per second (EPS) and per-thread variance $\sigma$.
    \item \textbf{Memory Bandwidth \& Operations (\texttt{sysbench memory}):} Evaluates memory transfer rates (MiB/s) and operations per second.
    \item \textbf{Hardware PMU Cache Miss Rates:} Hardware performance counters measuring L3 cache miss percentages.
    \item \textbf{Hardware Instruction Retirement (IPC):} Measures instructions retired per CPU clock cycle.
    \item \textbf{Network Loopback Throughput (\texttt{iperf3}):} High-bandwidth TCP socket loopback rate in Gbps.
    \item \textbf{Linux Kernel Compilation (\texttt{make kernel/}):} Multi-threaded parallel compilation measuring wall-clock build time.
\end{enumerate}

\subsection{Performance Results}
Table~\ref{tab:benchmark_results} reports the complete results across all 34 evaluated metrics for CFS/EEVDF, \texttt{scx\_optima}, \texttt{scx\_rusty}, and \texttt{scx\_rlfifo}.

\subsubsection{IPC Latency and Communication Throughput}
In \texttt{perf bench sched pipe}, OPTIMA delivers an unprecedented \textbf{2.55\,$\mu$s ping-pong latency}, representing an \textbf{84.1\% latency reduction} compared to CFS (16.06\,$\mu$s) and beating both \texttt{scx\_rlfifo} (4.36\,$\mu$s) and \texttt{scx\_rusty} (6.19\,$\mu$s). Throughput surges to \textbf{392,691 ops/s} (a \textbf{6.3$\times$ speedup} over CFS). This performance directly validates our synchronous IPC fast-path: by avoiding cross-CCX migration on \texttt{SCX\_WAKE\_SYNC}, cache lines remain hot in L1/L2 caches. In \texttt{iperf3} network loopback, OPTIMA achieves \textbf{111.47 Gbps}, nearly doubling CFS (57.58 Gbps) and outperforming \texttt{scx\_rlfifo} (62.03 Gbps).

\subsubsection{Real-Time Latency and Jitter Suppression}
In POSIX real-time jitter evaluation (\texttt{cyclictest}), OPTIMA achieves the lowest average jitter (\textbf{21.27\,$\mu$s}) and suppresses worst-case jitter spikes by \textbf{94.6\%} (450\,$\mu$s vs. 8,383\,$\mu$s on CFS). In pro-audio DSP, OPTIMA achieves \textbf{31.71\,$\mu$s} turnaround latency with \textbf{zero audio buffer underruns} (0.00 xruns vs. 3.67 on CFS). Similarly, in game server physics simulation, OPTIMA eliminates frame drops entirely (\textbf{0.000\% desync rate}).

\subsubsection{Software Compilation and Compute Throughput}
By removing artificial work-stealing barriers and enabling idle E-cores to drain shared queues, OPTIMA cuts kernel compile time from 11.63s down to \textbf{6.03s} (a \textbf{48.2\% reduction}), matching \texttt{scx\_rusty} (5.67s) and \texttt{scx\_rlfifo} (5.83s). In \texttt{sysbench memory}, OPTIMA achieves highest-in-class bandwidth (\textbf{12,394.80 MiB/s}) and operation rates (\textbf{12,692,281 ops/s}), representing a \textbf{+12.8\% gain} over CFS. Furthermore, thread fairness variance $\sigma$ drops by \textbf{98.0\%} (46.48 vs. 2303.38 on CFS), demonstrating optimal cross-core workload balancing.

\section{Discussion and Limitations}
\label{sec:discussion}

Our comprehensive evaluation across 34 metrics reveals both significant microarchitectural strengths and principled trade-offs inherent to specialized eBPF scheduling on asymmetric multiprocessors. In this section, we analyze the underlying systems mechanisms governing these trade-offs and delineate the operational limitations of our approach.

\subsection{Workload Trade-offs and Architectural Specialization}
The empirical results demonstrate a clear bimodal performance profile:
\begin{itemize}
    \item \textbf{Sub-Microsecond Latency and Real-Time Wins:} In workloads characterized by synchronous communication (perf pipe, iperf3 socket loopback) and strict timing bounds (pro-audio DSP, game server ticks, POSIX jitter), OPTIMA achieves decisive improvements: an 84.1\% reduction in pipe latency, a 94.6\% reduction in jitter spikes, and zero audio underruns or frame drops. These gains stem directly from architectural alignment: synchronous wakers bypass scheduling domains, and real-time tasks are strictly segregated onto Performance cores via continuous knapsack allocation.
    \item \textbf{High-Concurrency and Memory-Bound Trade-offs:} Conversely, in throughput-oriented database and proxy workloads (Production Redis, Cloud API Gateway), CFS outperforms OPTIMA by 14--30\%. These applications exhibit thousands of short, non-blocking requests with highly volatile burst runtimes that challenge our EWMA burst estimation. Under rapid connection multiplexing, static or slow-converging EWMA values misclassify short batch tasks as compute-bound, intermittently routing them to Efficiency cores or incurring queue rebalancing delays.
\end{itemize}

\subsection{Peer Preemption and the Schbench Latency Trade-off}
A notable finding in Table~\ref{tab:benchmark_results} is the behavior under \texttt{schbench}: OPTIMA's wakeup P50 latency is 1,996.67\,$\mu$s compared to CFS's 10.00\,$\mu$s, yet OPTIMA's P99 tail is \textbf{47.9\% lower} than CFS (2,007.33\,$\mu$s vs. 3,852.00\,$\mu$s) and 7.7$\times$ lower than \texttt{scx\_rusty} (15,472.00\,$\mu$s). Furthermore, OPTIMA exhibits an exceptionally tight distribution between P50 and P99 (differing by only 10.66\,$\mu$s: 1,996.67\,$\mu$s vs. 2,007.33\,$\mu$s).

This behavior is an intentional consequence of \textbf{Rule 2 of the Online Admissible Preemption Filter (OAPF)}:
\begin{equation*}
w_{\mathrm{curr}}(c) \ge w_{\mathrm{wake}} \implies \text{Prune candidate } c
\end{equation*}
In \texttt{schbench}, all worker threads share identical default nice levels ($w = 100$). When a worker wakes to process a simulated request, all candidate Performance cores are occupied by running peers with identical weight ($w_{\mathrm{curr}} = w_{\mathrm{wake}} = 100$). By Rule 2, OPTIMA strictly refuses to preempt a running peer of equal priority, preventing context-switch thrashing and cache evictions. The waking thread is enqueued at the head of the dispatch queue, waiting deterministically for the current running thread's minimum quantum ($\tau_{\min} = 2\,\text{ms}$) to expire. This creates an expected P50 wakeup delay near $\tau_{\min} \approx 2,000\,\mu\text{s}$. 

Conversely, CFS employs aggressive peer preemption based on instantaneous virtual runtime lag ($v_{\text{runtime}}$), yielding near-instantaneous P50 wakeups (10\,$\mu$s). However, under heavy concurrency, this causes cascading preemption storms where running threads are repeatedly interrupted before completing their compute phases, causing queue instability and exploding P99 tails to 3,852\,$\mu$s. OPTIMA trades median latency for tail predictability, guaranteeing that once a thread begins execution, it completes its quantum without interruption.

\subsection{Sysbench Compute Throughput and Thread Fairness}
In \texttt{sysbench cpu}, all three \texttt{sched\_ext} schedulers cluster around ~6,000 EPS within the 12-thread isolated partition, whereas CFS achieves 11,712 EPS. On unpartitioned bare metal across all 24 logical execution threads, OPTIMA achieves 11,692 EPS (comparable to CFS at 12,306 EPS). The critical differentiator lies in thread fairness: under CFS, individual thread event completions exhibit extreme variance ($\sigma = 2,303.38$), with some threads starved on slower cores while others surge ahead. Under OPTIMA, per-thread variance drops by \textbf{98.0\%} down to $\sigma = 46.48$. This demonstrates that OPTIMA's density-based knapsack balancing ensures uniform compute progress across asymmetric cores at the expense of uncoordinated thread racing.

\subsection{Extensible Scheduler Overheads in Dynamic Process Lifecycles}
In the parallel Linux kernel compilation benchmark (\texttt{make kernel/}), the wall-clock build time is 6.03s for OPTIMA, matching \texttt{scx\_rusty} (5.67s) and \texttt{scx\_rlfifo} (5.83s), but lagging native CFS (3.29s). In earlier iterations of OPTIMA, build time was 11.63s due to an artificial queue barrier that prevented idle Efficiency cores from stealing tasks enqueued for Performance cores. Removing this barrier and enabling unconstrained asymmetric work-stealing reduced compilation time by \textbf{48.2\%} (11.63s $\to$ 6.03s).

However, all \texttt{sched\_ext} schedulers remain ~83\% slower than CFS on this workload. The root cause is microarchitectural trampoline overhead: kernel compilation executes tens of thousands of short-lived compiler processes (\texttt{gcc}, \texttt{as}, \texttt{ld}). For each process creation and termination, \texttt{sched\_ext} invokes BPF struct-ops hooks (\texttt{ops.init\_task}, \texttt{ops.exit\_task}, \texttt{ops.select\_cpu}, \texttt{ops.enqueue}). While each invocation costs only a few hundred nanoseconds, the cumulative overhead across hundreds of thousands of process lifecycles imposes a measurable penalty compared to in-kernel CFS C code that optimizes process creation paths natively.

\subsection{Limitations and Future Work}
Several open challenges remain for extensible asymmetric scheduling:
\begin{enumerate}
    \item \textbf{Hardware Platform Diversity:} Our evaluation focuses on an asymmetric architecture with Performance and Efficiency cores sharing L3 cache. Future work must validate OPTIMA on disparate architectures, including ARM big.LITTLE mobile SoCs, Intel hybrid desktop processors with Hardware Feedback Interface (HFI), and multi-socket NUMA servers.
    \item \textbf{Energy and Thermal Dynamics:} While our knapsack formulation allocates long-running batch tasks to E-cores to maximize parallel energy efficiency, explicit integration with Energy-Aware Scheduling (EAS) models and dynamic voltage/frequency scaling (DVFS) governors remains an active research direction.
    \item \textbf{Dynamic Burst Estimation in Complex Runtimes:} For JIT-compiled languages and asynchronous actor systems where execution bursts vary non-linearly, incorporating compiler-assisted hinting or statistical quantile tracking into BPF maps would refine task density estimates.
\end{enumerate}

\section{Conclusion}
\label{sec:conclusion}

In this paper, we presented \textbf{OPTIMA}, an extensible operating system scheduler for asymmetric multiprocessors implemented in Linux \texttt{sched\_ext} eBPF. By replacing empirical fair-share heuristics with formal combinatorial optimization paradigms---Smith's Rule WSPT density ordering, Online Admissible Preemption Filtering (OAPF), continuous Dantzig knapsack partitioning, and synchronous IPC zero-lag dispatch---OPTIMA delivers principled scheduling foundations. Rigorous isolated empirical evaluation across 16 workloads demonstrates up to a 6.3$\times$ increase in IPC throughput, an 84.1\% reduction in pipe latency, a 94.6\% reduction in worst-case real-time latency spikes, and zero real-time audio drops. Our transparent analysis of workload trade-offs elucidates the conditions under which extensible scheduling excels, characterizes trampoline overheads under heavy process fork/exec storms and connection multiplexing, and establishes a principled empirical foundation for future asymmetric multiprocessor schedulers.
